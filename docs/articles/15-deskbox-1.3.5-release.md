# DeskBox 1.3.5：把越来越乱的 Windows 桌面，重新变成一个可工作的空间

> 本文为 DeskBox 1.3.5 的发布前说明，功能和文字以正式发布版本为准。

## 如果你第一次听说 DeskBox

可以先把 DeskBox 理解成一层放在 Windows 桌面上的工作界面。

它最主要的用途，是用“文件格子”整理桌面上的文件和文件夹：你可以创建一个收纳格子，也可以把已有的真实文件夹映射到桌面上；文件仍然是 Windows 的普通文件，资源管理器仍然可以正常使用。不同的是，你不必再把桌面当成一块堆放文件的空白区域，而是可以按项目、用途和工作习惯，给它安排出几个稳定的区域。

在文件整理之外，DeskBox 还提供待办、随记、桌面搜索、天气、音乐和胶囊等轻量组件。这些功能不是为了把桌面塞满，而是补上 Windows 原生桌面缺少的几个常用入口：临时记一件事、保存一段内容、看一眼天气、控制正在播放的音乐，或者快速找到文件。

所以，DeskBox 不是单纯的桌面美化工具，也不是要替代资源管理器。它更像是一个以桌面整理为核心、再补齐常用小组件的 Windows 工作面。

### DeskBox 适合怎样开始使用？

如果你刚安装 DeskBox，不需要一开始就研究所有功能，可以先按这个顺序：

1. 创建一个文件格子，或者映射一个已经存在的项目文件夹；
2. 用“桌面整理”预览并处理已经堆在桌面上的文件；
3. 为新出现的文件设置自动整理规则；
4. 再根据需要增加待办、随记、搜索、天气和音乐；
5. 如果几个格子属于同一个项目，再把它们合并成一个可切换的工作面。

这样使用，DeskBox 的价值会比较容易理解：它不是让桌面看起来更复杂，而是让文件有入口、信息有位置，常用内容能够更快回到手边。

## 这次 1.3.5，我到底在解决什么问题？

DeskBox 由我一个人维护。1.3.5 是投入时间比较长的一次更新，原因并不是功能数量本身，而是这次改动触及了文件真实路径、桌面整理、格子合并、文件监听和窗口恢复等多个基础环节。

这类功能不能只在界面上“看起来能用”。我需要反复测试下载中的文件、网络目录、权限不足、窗口切换、显示器变化、休眠唤醒和各种拖放情况。很多时间花在用户平时不一定注意到的细节上：文件夹暂时不可用时不能显示成空的，切换格子时不能把窗口重新挪走，拖动排序时不能因为鼠标经过某个位置就提前改变文件顺序。

因此，1.3.5 的重点不是简单罗列“新增了几个功能”，而是把 DeskBox 的主线补完整：

> 让桌面上的文件有地方可去、有结构可看；在这个结构之上，信息和工作上下文也可以快速切换。

## 一、桌面一键整理：先看清楚要搬什么，再移动真实文件

很多整理工具的问题，不是不能分类，而是分类之后用户不知道文件究竟去了哪里。

真实桌面也不像一个干净的测试目录。一个压缩包可能是刚下载的安装程序，也可能是正在使用的项目资料；一个文件夹可能只是临时入口，也可能正被其他软件使用。只按扩展名把所有东西直接搬走，效率看起来很高，使用时却很难放心。

1.3.5 的桌面整理采用“预览优先”。进入 `设置 → 文件格子 → 桌面整理`，或从托盘选择“整理桌面”，DeskBox 会先扫描桌面并生成整理计划。

整理计划会按收纳目标显示卡片，而不是只给一个“发现 27 个文件”的数字。每张卡片会展示文件预览、分类、目标格子或新建文件夹、最终真实路径，以及明确不会移动的项目。

每张卡片还可以单独控制：

- 暂时跳过某一类文件；
- 把目标改成已有文件格子；
- 选择新建收纳位置；
- 只整理图片和文档，把安装包或压缩包留在桌面。

这背后的产品取舍很明确：自动化可以减少重复操作，但不能在用户不知道结果的情况下替用户决定文件路径。

> [图片占位：展示桌面整理预览窗口，标注文件预览、目标位置、不会移动的项目和确认整理按钮]

### 哪些文件会被保留？

DeskBox 会对不适合立即移动的项目保持谨慎，常见情况包括：文件夹、仍在写入的文件、临时文件、下载或解压中的文件、云盘占位文件、暂时不可用的网络位置、无权限访问的项目，以及单个超过 100 MB 的大文件。

快速整理还限制为最多 200 个文件、累计 100 MB。超过部分会继续留在桌面，等下一次处理，不会为了追求“桌面一次清空”而强行执行。

桌面整理是真实文件操作，不是隐藏图标或改变显示方式。确认后，符合条件的文件会移动到目标位置；完成后可以通过结果页或通知中的撤销入口恢复这次批次。第一次使用时，我建议先用一个不重要的测试文件走完整流程，确认目标位置符合自己的习惯，再处理整个桌面。

详细操作：[DeskBox 桌面一键整理与自动整理](02-desktop-organization.md)。

## 二、自动整理：解决“今天整理完，明天又乱了”

一键整理解决的是已经积累的混乱。桌面真正难以保持整洁，是因为浏览器下载、微信接收、截图导出、视频渲染和压缩解压每天都会产生新文件。

自动整理默认关闭。启用时，DeskBox 会记录当时的桌面基线，已经存在的文件不会因为打开开关就被追溯搬走；之后出现的新文件，只有在匹配有效规则并且写入稳定后，才会进入整理流程。

文件名出现，并不代表文件已经准备好。下载和聊天接收往往会先创建文件，再持续写入内容。如果过早移动，可能造成文件占用、内容不完整或解压过程被打断。因此 1.3.5 会等待文件进入稳定状态，并额外判断下载增长、临时后缀、压缩包处理、解压和同路径替换。

没有有效目标规则、状态无法确认或超过限制的文件，会留在原处。规则绑定的是格子的稳定身份，不会因为格子改名、移动或加入格子组就突然失效。

我的建议是先从一个明确规则开始，例如“图片进入图片格子”，观察几天后再增加文档、视频和压缩包。自动整理应该减少注意力消耗，而不是让人每天检查它有没有做错事。

## 三、文件格子：桌面整理不是把文件摆好看，而是建立可使用的结构

DeskBox 的文件格子有两种常见用法。

收纳格子拥有自己的收纳目录，适合接收主动拖入的文件，拖入行为可以按需要选择复制或移动。映射文件夹格子则连接一个已经存在的真实目录，格子展示的就是那个目录里的内容，不会额外复制一份，也不会把网络文件变成云端副本。

这几个边界需要区分清楚：

- 文件格子的复制或移动，可能改变文件的真实路径；
- 映射文件夹只是展示真实目录；
- 格子组合只改变桌面上的组合和切换方式，不合并真实文件夹；
- 自动叠放只改变格子内的展示方式，不移动文件。

1.3.5 还重点处理了“文件明明还在，格子却像空了”的问题。网络盘断开、云盘离线、权限不足或目录正在扫描时，读取结果可能是不完整的。现在 DeskBox 会区分真正的空目录、部分结果、不可用和无权限状态；暂时不可用时保留上一次可用快照，临时刷新失败时尽量保留数量和手动排序。

映射路径切换后，旧路径产生的延迟监听事件也不会随意跑进新目录。这些优化不一定能在宣传图上看见，却决定了文件格子能否长期使用。

## 四、格子合并：减少窗口，不牺牲每个格子的独立性

一个项目经常同时需要项目文件、待办清单、灵感随记和参考资料。全部展开会占满桌面，全部收起又不方便访问。格子组解决的正是这个矛盾。

格子组不会把几个文件夹合成一个目录，也不会把成员内容混成一份数据。它让多个格子共享一个桌面表面，成员的文件、待办和随记仍然独立保存，解散组合也不会删除这些内容。

### 为什么把切换放在标题栏？

我考虑过第二行标签、内容区按钮、外置导航条和堆叠卡片，但这些方案都容易让导航本身变成新的视觉负担。标题栏本来就负责表达“当前是谁”和“这个窗口属于什么”，因此 1.3.5 把成员选择器放在现有标题栏中，不额外占用内容空间。

当前有三种切换方式：

- 点击标题栏的当前成员，打开列表并直接选择目标；
- 指针位于成员选择器热区时使用滚轮切换前后成员；
- 聚焦选择器后，用键盘打开列表，或使用 `Ctrl+Tab` / `Ctrl+Shift+Tab` 前后切换。

滚轮只在选择器区域生效。在文件内容里滚动仍然是滚动文件列表，在标题拖动区域也不会误切换成员。它是加速路径，不会取代点击和键盘。

切换时，窗口的位置、大小、锁定状态、层级以及展开或胶囊状态不会被重新设置。你可以在同一个工作面里处理文件，切到待办更新下一步动作，再切到随记记录想法，最后切回文件继续拖放，不需要重新寻找三个窗口。

> [动图占位：展示文件、待办、随记在同一格子组中切换，窗口位置保持不变]

当前格子组需要稳定的标准或紧凑标题栏。悬浮、隐藏或系统标题栏模式不适合参与组合时，界面会说明原因，不会为了完成合并而偷偷修改外观设置。成员可以移出，整个格子组也可以解散；长按标题可以将成员拖出。

完整说明：[DeskBox 格子组](10-widget-groups.md)。

## 五、拖放、排序和同步：把不容易察觉的错误提前挡住

1.3.5 的拖放优化，重点不是增加动画，而是让“拖到哪里”和“要做什么”更明确。

文件格子内部排序时，跨屏拖动不会在每一次 `DragOver` 就修改列表，而是显示主题色插入线，松开鼠标后一次提交最终顺序。独立格子和格子组内的文件成员使用一致的插入计算，拖动过程中不会因为列表重排而跳动。

DeskBox 也会区分不同目标：拖到文件夹项目上是进入文件夹或执行文件操作，拖到空白区域是调整顺序，从格子拖到资源管理器、微信或浏览器是交给外部应用，拖入格子则按照当前设置决定复制还是移动。

搜索方面，1.3.5 增加了根目录清单、安全对账和更细的健康诊断。磁盘离线、权限不足、扫描取消或 USN journal 断档时，不会简单地把不完整结果当成“目录为空”，有效索引也不会因为一次临时故障就被误删。

此外，DeskBox 对 Windows 10/11 的云母、亚克力背景增加了能力回退，并补充了休眠唤醒、远程桌面、Explorer 重启和显示器变化后的恢复检查；图标、快捷方式、菜单、通知、五种语言资源和版本更新说明也做了细节修整。

## 我建议怎样开始使用 1.3.5？

先创建一个文件格子，给它设置稳定的收纳位置；如果已有项目目录，直接映射它，不必先搬家。然后打开桌面整理，检查文件、目标格子和真实路径，确认后再执行。自动整理先只配置一个明确规则，等确认行为符合习惯，再逐步增加类型。

当一个项目需要文件、待办和随记时，把它们合并为格子组。先用标题栏点击切换，熟悉之后使用选择器热区滚轮或 `Ctrl+Tab`，会比在桌面上寻找多个窗口更快。天气、音乐和其他不需要持续展开的内容，可以最后再收成胶囊。

需要特别记住：自动叠放只改变展示；桌面整理、文件格子的移动和自动整理，才可能改变真实文件路径。

## 这次更新的边界

DeskBox 不替代 Windows 资源管理器；格子组不合并真实目录；自动整理不追溯处理开启前已有的文件，也不会移动无法确认稳定状态的项目。天气需要网络和可用数据源，QuickLook 依赖系统中可用的预览处理器，Windows 通知、媒体会话和文件监听会受系统设置、权限和当前环境影响。

DeskBox 是本地优先的软件，不要求账号，但本地优先不等于加密。Tags 和 SystemMonitor 也不是 1.3.5 已实现的功能。

## 写在最后

我不希望 DeskBox 把所有人的桌面都变成一张空白壁纸。有人需要把当前项目放在桌面上，有人需要随手接收文件，也有人只想在需要时快速找到天气、待办或一段随记。桌面应该服务于工作方式，而不是要求所有人遵循同一种规则。

如果说 1.3.4 更多是在打磨基础体验，1.3.5 则是在回答 DeskBox 为什么存在：让桌面不只是文件的临时堆放处，也可以成为开始工作、切换上下文和收回注意力的地方。

这次更新花了比较长的时间，很多精力都放在真实文件、异常状态和窗口细节的测试上。文章不可能把每一处变化都写完，仍然有不少细节需要你在使用中自己发现。也欢迎把实际遇到的问题和使用方式反馈给我，这会继续影响 DeskBox 后面的方向。

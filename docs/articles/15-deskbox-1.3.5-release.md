# DeskBox 1.3.5：这一次，我们认真解决了桌面越来越乱的问题

> 本文是一篇发布前版本说明，功能和文字以 1.3.5 正式发布版本为准。

很多 Windows 用户都有过这样的经历：

刚安装完系统时，桌面很干净。过了一段时间，下载的安装包、临时导出的图片、客户发来的资料、还没来得及归档的文档，开始一层层堆在桌面上。桌面上的文件越来越多，真正需要找东西时，却只能在一堆图标里慢慢翻。

于是我们会尝试给文件建文件夹，或者把文件拖到某个目录里。但问题往往不是“不会建文件夹”，而是工作正在进行的时候，文件不断从浏览器、微信、聊天软件和各种工具里出现。整理一次很容易，坚持每次都整理，几乎不可能。

DeskBox 1.3.5 主要就是从这个问题开始的。

这次更新没有把重点放在“再增加几个小组件”上，而是先把 DeskBox 最重要的主线补完整：

> 让 Windows 桌面上的文件有地方可去、有结构可看，而且这个结构不会因为你继续工作就马上失效。

在此基础上，我们再把待办、随记、搜索、天气和音乐这些 Windows 原生桌面缺少的轻量能力，放到同一个工作面里。文件整理是核心，小组件是补齐体验，格子则是连接两者的基本单位。

> [图片占位：展示一个整理前后对比的 Windows 桌面，包含文件格子、待办格子、随记格子和收纳后的桌面文件]

## 这次更新，最重要的不是“多了什么”，而是“桌面整理终于变成了一套流程”

在 1.3.4 里，DeskBox 已经可以把文件、文件夹、待办和随记放进桌面格子中。但如果桌面本身已经堆满了文件，用户仍然需要自己一点点拖动、分类和规划。

所以 1.3.5 做的第一件事，是把“整理桌面”从一个想法，变成一个可以检查、可以确认、可以撤销的实际流程：

1. 先扫描桌面，知道现在有哪些文件。
2. 按文件类型形成收纳建议。
3. 在执行前看到每一类文件会去哪里。
4. 用户可以取消某一类，也可以修改它的目标位置。
5. 确认后才移动真实文件。
6. 完成后给出结果，并保留撤销入口。

这和“点一下，然后软件替你把整个桌面搬空”是两件完全不同的事。

我一直认为，文件整理工具最需要建立的不是一种神奇感，而是信任感。用户愿意把文件交给软件，前提是他知道软件准备做什么，也知道哪些文件不会被处理。

## 一、桌面一键整理：先告诉你文件要去哪里，再帮你移动

### 为什么不直接按扩展名自动搬走？

因为真实桌面并不像一个干净的测试目录。

一个叫“最终版”的文件，可能是图片，也可能是设计源文件；一个压缩包，可能是刚下载的安装程序，也可能是当前项目还没解压的资料；一个文件夹，可能是用户临时放在桌面上的项目入口，也可能是某个软件正在使用的工作目录。

如果整理工具只看扩展名，然后毫不解释地移动文件，功能看起来很自动，结果却很难让人放心。

1.3.5 的桌面整理使用了“预览优先”的思路。打开 `设置 → 文件格子 → 桌面整理`，或者从托盘菜单进入“整理桌面”，DeskBox 会先生成一份整理计划。

计划不是一行“发现 27 个文件”这么简单，而是按照收纳目标展示卡片。每张卡片会告诉你：

- 这一组里有哪些文件；
- DeskBox 根据什么类型把它们归到一起；
- 当前准备放入哪个文件夹或文件格子；
- 如果选择新建收纳位置，最终真实路径是什么；
- 哪些项目符合条件、会被移动；
- 哪些项目被保留在桌面，以及保留原因。

卡片中的文件会以图标和名称呈现，而不是只给一个抽象的数量。窗口变宽时，卡片会增加列数；窗口变窄时，内容会换行并在卡片内部滚动。这样做的目的很朴素：整理之前，用户应该有机会看一眼具体内容，而不是面对一个无法判断的统计数字。

> [图片占位：展示桌面整理预览窗口，重点标注“文件预览”“目标位置”“不会移动的项目”和“确认整理”按钮]

### 每一类文件都可以单独决定

桌面整理不是一个只有“开始”和“取消”的黑盒操作。

在 1.3.5 中，每张分类卡片都可以单独控制：

- 暂时不想整理这一类，可以取消勾选；
- 不想新建文件夹，可以改为放入已有的文件格子；
- 原来的目标不符合当前项目，可以重新选择目标；
- 只整理图片和文档，安装包、压缩包留在桌面，也可以这样做。

这也是我们在设计时比较看重的一点：自动化不应该把选择权拿走。真正好用的自动化，是把重复劳动提前做掉，但在不可逆的动作之前给用户一个清晰的确认点。

### 哪些文件会被保留？

为了避免一次整理打断正在进行的工作，DeskBox 会对不适合立即移动的项目保持谨慎。常见的保留情况包括：

- 文件夹或当前流程暂不处理的目录项目；
- 仍在写入、大小还在变化的文件；
- 临时文件、下载中的文件或压缩处理中的文件；
- 云盘占位文件、网络位置暂时不可用的文件；
- 没有权限访问、无法确认状态的项目；
- 单个超过 100 MB 的大文件。

快速整理还会限制单次批次的规模，最多处理 200 个文件、累计 100 MB。超过这部分不会被强行塞进同一次任务，而是继续留在桌面，等用户下一次确认处理。

这不是为了让功能显得保守，而是因为桌面整理一旦涉及真实文件路径，就不应该为了追求“全部清空”而忽略文件状态。

### 这次整理会不会真的移动文件？

会。

桌面整理不是隐藏图标，也不是改变 Windows 桌面的显示方式。确认执行后，符合条件的文件会被移动到目标收纳位置，文件的真实路径会发生变化；整理完成后，可以通过结果页或通知中的撤销入口恢复这次批次。

所以第一次使用时，我建议先拿一个不重要的测试文件体验完整流程，确认目标文件夹和自己的收纳习惯，再处理整个桌面。

详细操作可以继续阅读：[DeskBox 桌面一键整理与自动整理](02-desktop-organization.md)。

## 二、自动整理：解决“今天整理完，明天又乱了”

一键整理解决的是“已经乱了怎么办”。

但桌面真正让人疲惫的地方，是它会持续产生新文件：浏览器下载、微信接收、截图工具导出、剪辑软件渲染、压缩软件解压，每天都有新的文件从不同的应用流到桌面。

如果每次都要手动整理，桌面很快就会恢复原状。因此 1.3.5 又补上了第二条路径：自动整理。

### 自动整理不是打开开关就搬走整个桌面

自动整理默认关闭。启用时，DeskBox 会把当时桌面上已经存在的内容记录为一个基线。基线之前的文件不会因为你打开开关就被追溯搬走；它们仍然可以通过“一键整理”单独预览和处理。

开启之后，自动整理主要关注两件事：

1. 这个文件是不是在启用之后才出现的；
2. 这个文件是不是已经真正写完，可以安全处理。

这意味着，自动整理更像一个有边界的桌面收件员，而不是一个一直盯着桌面、看到文件就立即搬走的搬运器。

### 为什么下载文件不会一出现就被搬走？

因为文件名出现，不代表文件已经准备好。

下载、聊天接收和导出文件经常会先创建一个文件，然后持续写入内容。如果文件刚出现就移动，可能遇到以下问题：

- 文件还没下载完成；
- 文件大小仍在变化；
- 文件被其他应用占用；
- 解压软件还在向目录写入内容；
- 同一个路径正在被新文件替换。

1.3.5 会等待文件进入相对稳定的终态，并对下载增长、临时后缀、压缩包处理、解压和同路径替换做额外判断。只有通过稳定性检查、匹配有效规则的文件，才会进入自动整理流程。

如果没有有效的目标规则，或者文件无法确认状态，DeskBox 会让它留在原处。规则也不会因为文件格子改名、移动或加入格子组就突然丢失，因为规则绑定的是格子的稳定身份，而不是标题文字。

> [动图占位：展示一个下载文件从出现、持续写入、保持在桌面，到稳定后自动进入目标文件格子的完整过程]

### 我建议怎样开启自动整理？

不要第一次安装就把所有规则都打开。更稳妥的方式是：

1. 先用一键整理把桌面现有文件分出基本结构；
2. 为一个最明确的目标设置规则，例如“图片”进入图片格子；
3. 下载一个小文件，观察它是否在完成后进入预期位置；
4. 确认规则符合自己的工作方式后，再增加文档、视频、压缩包等类型。

自动整理应该减少你的注意力消耗，而不是让你每天检查它有没有做错事。

## 三、文件格子：不是把文件“摆好看”，而是让桌面拥有可使用的结构

DeskBox 的文件格子有两种常见用法。

第一种是收纳格子：它拥有自己的收纳目录，用于接收你主动拖入、复制或移动进去的文件。

第二种是映射文件夹格子：它连接一个已经存在的真实目录，格子展示的就是那个目录里的内容。

这两个概念看起来相近，但边界很重要。

- 收纳格子可以成为桌面文件的长期入口，拖入行为可以按需要选择复制或移动；
- 映射文件夹格子不会把目录复制一份，也不会把网络文件变成云端副本，它只是把真实目录展示到桌面；
- 格子组只改变格子的组合和切换方式，不会把多个真实文件夹合并成一个目录；
- 自动叠放只改变格子里的展示方式，不等于真实移动文件。

我希望 DeskBox 给桌面增加一层结构，但不把用户锁进一个封闭的文件系统里。资源管理器依然可以正常使用，文件也仍然是 Windows 能直接识别的普通文件。用户可以从资源管理器进入目录，也可以从格子中拖出文件交给其他应用。

### 1.3.5 重点修复了“文件明明还在，格子却像空了”的问题

文件格子最让人不安的情况，不是没有动画，而是目录暂时不可用时，软件把它误认为“空目录”。

网络盘断开、云盘暂时离线、权限不足、目录正在重新扫描时，读取结果可能是不完整的。如果这时直接用空结果覆盖界面，用户会以为文件消失了，手动排序也可能被重置。

1.3.5 对文件夹读取结果做了更清晰的区分：

- 确认没有内容，才显示真正的空目录；
- 读取不完整时，保留已知内容并标注状态；
- 位置暂时不可用时，保留上一次可用快照；
- 权限不足时，明确反馈问题，而不是伪装成空目录；
- 临时刷新失败时，尽量保留之前的数量和手动排序。

对于映射文件夹，程序还会区分不同一轮监听任务。旧路径产生的延迟事件，不应该在你切换路径以后跑进新目录里。这类优化不会在宣传图上特别显眼，但它决定了文件格子能不能长期使用。

## 四、格子合并：减少桌面窗口，不牺牲每个格子的独立性

当桌面整理出基本结构以后，新的问题会出现：

一个项目可能同时需要项目文件、待办清单、灵感随记和参考资料。如果把所有格子都展开，桌面会再次变得拥挤；如果全部收起来，又失去了随手访问的优势。

所以这次我们加入了格子组合。

### 格子组到底解决什么问题？

格子组不是把几个文件夹强行合成一个目录，也不是把所有内容混成一份数据。

它解决的是桌面空间和上下文切换的问题：多个格子保留自己的文件、任务和内容，但共享一个桌面表面。你可以把“项目文件”“项目待办”“项目随记”放在同一组里，需要时切换当前成员，不需要时只占用一个位置。

换句话说：

> 合并的是桌面上的工作面，不是文件系统里的真实目录。

成员的文件路径、待办内容、随记数据和自己的业务状态仍然独立存在。解散格子组也不会删除这些数据，只是恢复为独立格子。

### 为什么把切换放在标题栏？

我们在设计过程中考虑过很多更明显的方案：增加第二行标签、在内容区放一排按钮、做一个常驻的外置导航条，甚至把格子做成堆叠卡片。

这些方案都能让“切换”变得显眼，但也会带来另一个问题：格子本来是桌面上的轻量工作面，导航本身却变成了新的视觉负担。

最终，1.3.5 把成员选择器放回现有标题栏。标题栏本来就承担了“我现在看的是谁”和“这个窗口属于什么”的身份信息，成员切换放在这里更符合用户的认知，也不会额外占用内容空间。

当前的切换方式有三种：

- 点击标题栏中的当前成员，打开成员列表，直接选择目标；
- 指针位于成员选择器区域时使用滚轮，切换前后成员；
- 聚焦选择器后，用键盘打开列表、选择成员，或使用 `Ctrl+Tab` / `Ctrl+Shift+Tab` 前后切换。

这里有一个容易忽略的细节：滚轮只在标题栏成员选择器的热区生效。指针在文件列表里滚动时，仍然是滚动文件；在标题拖动区域滚动时，也不会误切换成员。滚轮是加速路径，不会取代点击和键盘，也不会把整个格子变成“滚轮一碰就换页”的不可预测控件。

### 合并后，为什么切换会更快？

格子组合的效率不只来自少点几次鼠标，更来自它减少了工作上下文的重新建立。

如果项目文件、项目待办和项目随记分别散落在桌面不同位置，每次切换都要先找窗口，再确认当前内容，再把注意力拉回项目。组合以后，用户只需要在同一个标题栏里切换当前成员：窗口位置不变，大小不变，锁定状态不变，展开或胶囊状态也不因为切换被重置。

这意味着你可以建立自己的切换节奏：

1. 先在文件成员里处理资料；
2. 滚轮或 `Ctrl+Tab` 切到待办成员，更新下一步动作；
3. 再切到随记成员，记录刚刚产生的想法；
4. 切回文件成员继续拖放，不需要重新找回三个窗口。

它更像一个小型项目驾驶舱，而不是把几个窗口叠在一起。

> [动图占位：展示一个格子组在文件、待办、随记成员之间切换，重点表现窗口位置不变、标题栏显示当前成员、滚轮只在选择器区域生效]

### 怎样合并格子？哪些格子不能合并？

合并前，DeskBox 会检查参与合并的格子状态。当前格子组需要可持续显示的标准或紧凑标题栏；悬浮、隐藏或系统标题栏模式不适合作为组合成员时，界面会说明原因，不会为了完成合并而偷偷替你改掉外观设置。

这个限制是有意保留的。

格子组合需要一个稳定的标题栏来承载成员身份和切换入口。如果一个格子本身没有标题栏，或者标题栏只在特定状态下临时出现，组合后的导航就会变得不可靠。与其让用户合并成功后才发现无法找到成员，不如在合并前把原因说清楚。

合并之后，如果要把某个成员恢复成独立格子，可以从成员管理中移出；如果不再需要组合，也可以解散整个格子组。长按标题可以把成员拖出，这个动作和移动窗口的拖动区域做了区分，避免普通拖动时误触发。

## 五、文件拖动和排序：让“拖到哪里”与“要做什么”更明确

桌面格子最常用的动作仍然是拖放。1.3.5 对拖放和排序也做了不少调整，目标不是让动画更复杂，而是让用户在动作发生之前就知道结果。

在文件格子内部排序时，跨屏拖动不再随着每一次 `DragOver` 就修改列表。现在会在相邻项目之间显示一条主题色的插入提示线，鼠标松开后才一次性提交最终顺序。

这样做有几个好处：

- 拖动过程中不会因为列表反复重排而跳动；
- 跨显示器拖动时，更容易判断最终插入位置；
- 取消拖动时，不会留下中间状态；
- 独立文件格子和格子组里的文件成员使用一致的排序逻辑。

同时，DeskBox 会区分不同的拖放目标：

- 拖到文件夹项目上，是进入这个文件夹或执行对应的文件操作；
- 拖到空白区域，是调整文件在格子中的顺序；
- 从格子拖到外部应用，是把文件交给资源管理器、微信、浏览器等其他软件；
- 拖入格子时，则按照当前设置决定复制还是移动。

这几个动作在视觉上都叫“拖”，但实际含义不同。我们希望把这种差异解释清楚，减少“我只是想排序，结果文件被移动了”的意外。

## 六、那些不太显眼，但会决定体验是否可靠的优化

1.3.5 还有一些不会成为宣传标题的更新，但它们和桌面整理长期使用有关。

### 搜索不再因为一次不完整扫描就丢掉已有结果

桌面文件搜索需要索引。索引如果遇到磁盘离线、权限不足、扫描被取消、USN journal 断档或目录变化过快，不能简单地把这次不完整结果当成“现在目录就是空的”。

1.3.5 增加了根目录清单、安全对账和更细的健康诊断。创建、删除、重命名和硬链接变化可以增量处理；遇到日志断档时，会进行恢复或回退到目录索引。扫描覆盖范围、离线根目录、监听器状态和最近一次完整扫描时间，也会进入诊断信息。

对用户来说，最直接的变化是：一次临时的磁盘状态问题，不应该把原本能搜到的文件永久从结果里抹掉。

### Windows 10 和复杂窗口环境下的恢复更稳

DeskBox 使用了 Windows 的云母、亚克力等背景能力，但不同 Windows 版本、远程桌面、显卡和系统设置的支持情况并不完全一致。1.3.5 增加了按系统能力回退的背景方案，在不支持某种效果时使用主题色纯色背景，而不是让窗口失去可读性。

同时，程序对休眠唤醒、锁屏解锁、远程桌面、Explorer 重启和显示器变化做了轻量恢复检查。动画也会尊重减少动态和高对比度设置。

这些事情平时感觉不到，只有在电脑从睡眠中回来、换了显示器或重新连接远程桌面时，才会知道一个桌面工具是否真的考虑过 Windows 的真实使用环境。

### 图标、菜单、更新说明和多语言细节

这次还包含一些持续性的体验修整：

- 大尺寸的程序和快捷方式图标使用更合适的 Windows Shell 图标来源；
- 小图标的缩放更平滑，自动叠放中的图标也遵循尺寸设置；
- `.lnk` 快捷方式使用 Windows Shell 兼容路径启动；
- 文件格子内容菜单补齐标题样式、展开方式、关闭格子等操作；
- 剪贴板没有可用内容时，不再显示没有意义的“粘贴”；
- 设置中可以打开独立的版本更新说明窗口；
- 更新了桌面整理、诊断、拖放反馈和五种语言资源。

这些优化看起来零散，但共同指向一个目标：DeskBox 应该像一个稳定的桌面基础层，而不是几个功能拼在一起的演示程序。

## 1.3.5 推荐的使用顺序：先建立结构，再减少操作

如果你第一次使用 DeskBox 1.3.5，我建议不要一次打开所有能力。可以按下面的顺序建立自己的桌面：

### 第一步：先做一个明确的文件入口

创建一个文件格子，给它设置稳定的收纳位置。把工作中经常使用的项目目录，或者下载后最常处理的一类文件，先放到这里。

如果你已经有现成的文件夹，不需要搬家，直接创建映射文件夹格子即可。先让桌面上的入口和真实目录建立对应关系。

### 第二步：用一次预览整理处理旧文件

打开桌面整理，先看计划，不要急着确认。检查每张卡片的文件、目标格子和真实路径；不合适的分类取消勾选，或者修改目标位置。

确认桌面整理符合你的习惯后，再执行并观察结果。如果需要，使用撤销恢复刚刚的批次。

### 第三步：只为最明确的规则开启自动整理

例如，先让图片进入图片格子，或者让安装包进入一个专门的临时格子。规则越明确，自动整理越容易建立信任。等几天确认它符合你的工作方式，再逐步增加规则。

### 第四步：把同一个项目的格子合并

项目文件、项目待办、项目随记适合放在同一个格子组里。需要切换时点击标题栏成员选择器；熟悉以后，使用选择器区域的滚轮，或者 `Ctrl+Tab` / `Ctrl+Shift+Tab`，会比在桌面上寻找多个窗口更快。

### 第五步：最后再用胶囊和自动叠放降低视觉噪音

当桌面结构已经稳定后，可以把不需要持续展开的天气、音乐或随记格子收成胶囊，也可以在文件格子内部使用自动叠放来减少文件列表的视觉噪音。

这里要再次强调：自动叠放只是改变显示方式；桌面整理、文件格子的移动操作和自动整理，才可能改变真实文件路径。

## 我们没有在 1.3.5 里承诺什么？

这次更新有明确的边界：

- DeskBox 不替换 Windows 资源管理器，资源管理器仍然是完整的文件管理工具；
- DeskBox 不把格子组变成新的文件系统，合并格子不会合并真实文件夹；
- 自动整理不会追溯搬走开启前已经存在的全部文件；
- 自动整理不会处理无法确认稳定状态的文件；
- 天气数据需要网络和可用的数据源；
- QuickLook 预览依赖 Windows 可用的预览处理器，不是所有文件类型都能预览；
- Windows 通知、系统媒体会话和系统文件监听能力受系统设置、权限和当前环境影响；
- DeskBox 是本地优先的软件，不要求账号，但本地优先不等于加密，备份也不等于安全隔离；
- Tags 和 SystemMonitor 目前仍不是 1.3.5 的已实现功能。

我们更愿意把这些边界写清楚。一个桌面整理工具只有在用户知道它能做什么、不能做什么的时候，才真正值得长期使用。

## 写在最后：桌面不是越空越好，而是越容易回到工作状态越好

我们做 DeskBox，并不是想把每个人的桌面都变成一张“什么都没有”的壁纸。

有些人喜欢把当前项目放在桌面上，有些人需要随手接收文件，有些人希望天气和音乐一直可见，也有人只想在需要时唤出一个干净的工作面。桌面本来就应该服务于人的工作方式，而不是要求所有人遵循同一种整理规则。

所以 1.3.5 的方向不是“替你决定桌面应该长什么样”，而是提供几种更可靠的选择：

- 用文件格子建立桌面与真实目录之间的联系；
- 用一键整理处理已经积累的混乱；
- 用自动整理减少新文件不断堆积；
- 用格子组把同一个项目需要的上下文放到一个工作面；
- 用标题栏点击、局部滚轮和键盘切换，减少寻找窗口的时间；
- 用待办、随记、搜索、天气和音乐补上 Windows 桌面缺少的轻量信息入口。

如果说 1.3.4 更像是在把 DeskBox 的基础体验打磨得更稳定，那么 1.3.5 做的事情，就是开始回答 DeskBox 为什么存在：

> 桌面可以是文件的临时堆放处，也可以成为你每天开始工作、切换上下文和收回注意力的地方。

这就是我们准备发布 DeskBox 1.3.5 的原因。
